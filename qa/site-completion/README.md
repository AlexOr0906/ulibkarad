- Семь отдельных страниц: `/`, `/about/`, `/patients/`, `/adult-therapy/`, `/children-therapy/`, `/orthopedics/`, `/orthodontics-concept/`.
- 320/390/768/1440 × обычный режим/reduced motion/no-JS: 12 наборов, по 7 страниц (84 посещения, кроме дополнительных переходов).
- Один h1/main/header/footer, title/description, загрузка видимых изображений, отсутствие ошибок страницы/HTTP-ресурсов и горизонтального переполнения при прямой/обратной прокрутке.
- 47 уникальных ссылок/фрагментов: существующий HTTP-маршрут и целевой id. Это не проверка юридической достаточности документов; реальные файлы не получены.
- Клавиатура, видимый фокус, мобильное меню/Escape/возврат фокуса, открытие всех четырёх демонстрационных профилей и закрытие Escape.
- Услуга → команда → назад/вперёд → услуга → контакты. Контакты и команда остаются разделами главной.
- Дополнительная локальная проверка: вопросы родителей открываются/закрываются клавиатурой в обычном/reduced/no-JS; состояния 0/.5/1/.5/0 сцен ортопедии и ортодонтии на 390/1440 совпадают с прогрессом прокрутки.

Обнаруженная и исправленная ошибка: главная включала нативные межстраничные переходы статически, внутренние страницы — только через JavaScript. При no-JS/back-forward Chrome сообщал об отменённом переходе. Включение согласовано через JS, отмена обрабатывается; повторный полный прогон прошёл.

## Как получить отдельно

```sh
git fetch origin feature/site-completion qa/site-completion
# Читать отчёт, не переключая свою рабочую копию:
git show origin/qa/site-completion:qa/site-completion/README.md
git show origin/qa/site-completion:qa/site-completion/results.json
# Узнать отдельный коммит отчёта:
git log -1 --format=%H origin/qa/site-completion
```

Вершина qa-ветки отличается от проверенного кода только файлами qa/. Если нужно перенести только отчёт, cherry-pick вершины qa-ветки не требует переноса frontend-коммита. Перед cherry-pick сохранить свою работу; общие ветки автоматически не сливать.

Для запуска кода использовать собственный clone/worktree от указанного SHA. Сначала прочитать AGENTS.md и SITE-COMPLETION.md. `npm ci`, `npm run build`, затем локальный static preview dist. Наш проверенный preview работал на `http://localhost:4186/`; этот адрес не доступен на другом компьютере автоматически.

```sh
# При работающем preview:
node scripts/verify-site-completion.mjs
```

`PREVIEW_URL`, `BROWSER_PATH`, `WIDTHS` переопределяются переменными окружения. По умолчанию используется Chrome на Windows. Скрипт сохраняет новые кадры/JSON в игнорируемый work/verification/site-completion.

## Ограничения и открытые задачи

Это эмуляция в настольном Chrome, не физический телефон/Safari и не подтверждение плавности на конкретном устройстве. Нет backend, реальной отправки записи, CMS, поиска и анкет. Нет проверки медицинской достоверности, юридического соответствия или фактической готовности клиники. Исходный REQUIREMENTS-PLAN.md в копии отсутствует.

До запуска нужны реальные материалы, права на изображения, контакты, реквизиты, лицензия/документы, медицинское согласование, сверка требований и функционала записи. Подробности — CONTENT-REPLACEMENT.md проверенной ветки. Новая версия не публиковалась; main/Pages не меняются передачей этих отчётов.
