## Что готово

Полная демонстрационная страница `/orthopedics/` на общем `ServicePageContent`, внутри существующего `InternalPageLayout`. Единственные h1/main/header/footer. Named slot `scene` содержит локальный визуал; default slot полностью заменяет стандартное тело шаблона. Временный OrthopedicsPreviewIntro используется только в старом автономном preview.

Есть страницы `/`, `/about/`, `/patients/`; с главной через «Направления» → раскрыть «Ортопедия» → «О направлении» можно перейти в ортопедию. Остальные направления не заменены фиктивными услугами. Композиция/анимации согласованной главной не переделывались.

В текущем коде сцены: прежний WebP, макроплан → целая форма → один блик → статичный финал на последних 20% локального участка. Обычный scroll, локальная sticky-панель, без перехвата wheel/touch, без WebGL/видео/новых зависимостей. Reduced motion/no-JS показывают статичный финал без удлинённого участка.

Оба компонента на интегрированной странице получают autoMotion=false; существующий internal-lifecycle владеет initializer/cleanup. Автономный preview оставляет autoMotion=true. Не включать оба пути одновременно.

## Визуальный статус: что осталось

**Текущая анимация и старый исходник не приняты как финальное решение.** Не считать зелёные тесты согласованием дизайна.

Новая более чистая предметная иллюстрация сохранена в `design/orthopedics/crown-graphite-study-v2.png`; описание/происхождение — соседний README. Она подходит как кандидат для дальнейшей работы, но НЕ подключена к странице, не нарезана, не оптимизирована и не анимирована. Это отдельный исходник для передачи, не новая реализация.

Варианты дальнейшего движения, пока без выбора: раскрытие кадра при неподвижном предмете; прорисовка точного силуэта с проявлением изображения; смена освещения по совпадающим световым состояниям; композиция «предмет + отдельная макродеталь». Не выдавать обычное масштабирование старой картинки за новый рендер. Сцену с брекетами сейчас не разрабатывать; текущая задача остаётся ортопедией.

Медицинский текст, перечень помощи, врачи, стоимость, контакты и документы заменяются только по материалам клиники. Не придумывать процедуры/этапы лечения/прайс/гарантии. По лицензии только: **«Сведения будут добавлены после получения от клиники»**. Нет backend, реальной отправки формы и админки.

## Получение и запуск

Работать в собственной копии/ветке. Перед переключением сохранить свою работу. Не сбрасывать чужой checkout.

```powershell
git clone --branch codex/orthopedics-template-review --single-branch https://github.com/AlexOr0906/ulibkarad.git orthofamily-handoff
cd orthofamily-handoff
git rev-parse HEAD
git status --short
npm ci
npm run build
npm run dev -- --host 127.0.0.1 --port 4186
```

Node 24. Использовать существующий package-lock, не обновлять зависимости ради запуска. Если порт занят другой копией — выбрать свободный и проверить фактический URL, а не останавливать чужой процесс.

- http://localhost:4186/ — главная.
- http://localhost:4186/orthopedics/ — основной интегрированный адрес.
- http://localhost:4186/about/ — «О клинике».
- http://localhost:4186/patients/ — «Пациентам».
- http://localhost:4186/orthopedics-preview/ — прежняя автономная композиция для сравнения.
- http://localhost:4186/service-template-preview/ — техническая проверка шаблона.

При передаче локальный сервер на исходном компьютере обслуживал production dist этой копии на loopback: `python -m http.server 4186 --bind 127.0.0.1 --directory dist`. Это альтернативный способ просмотра после сборки; не запускать оба сервера на одном порту. Localhost доступен только на соответствующем компьютере, не является ссылкой для внешнего клиента.
