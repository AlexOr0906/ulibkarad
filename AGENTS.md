# Ортофэмили: совместная работа

Актуальные решения: `BRIEF.md`. Техническая визуальная основа и статус предложений: `DESIGN.md`. Ответственные и состояние этапов: `TASKS.md`. Исторические README/brief/status внутри `scrollcraft/builds/` описывают прежние итерации и не переопределяют эти документы. Прямые указания пользователя имеют приоритет; не запрашивайте повторно уже данное разрешение.

## Перед изменениями

- Проверьте текущую папку, `git status --short`, ветку, последние коммиты и используемый preview-процесс. Не считайте локальный сервер запущенным из этой же копии без проверки.
- У каждого разработчика отдельный clone/worktree и рабочая ветка. Не переключайте чужую папку, не сбрасывайте изменения, не делайте force push. Сохраняйте собственные изменения перед переключением или интеграцией.
- Прочитайте `.agents/skills/frontend-design/SKILL.md` и `.agents/skills/scroll-craft/SKILL.md` с нужными ссылочными материалами. Бриф проекта выше общих эстетических рекомендаций навыков. Происхождение, версии и лицензии перечислены в `.agents/skills/SOURCES.md`.

## Ветки и интеграция

Обновление владельцев: новая шапка/мобильное меню поручены B в `feature/header-navigation`. A не переделывает их параллельно и сохраняет текущую шапку до интеграции этой ветки. Контракт якорей: `#of-top`, `#of-about`, `#of-directions`, `#doctors`, `#contacts`. CTA `#of-visit` ведёт к контактам; ссылка с `data-of-visit` открывает существующее демо-окно без отправки. Шапка фиксирована сверху, 88px desktop / 72px до 767px. Сцена использует локальную `--of-header-height` с этими значениями. Текущие scroll-margin: 100px, у врачей на телефоне 84px. Новая шапка передаёт фактическую высоту при интеграции, не меняет IDs самостоятельно.

- Подготовительная ветка: `codex/orthofamily-team-base`, основана на опубликованном `5b79050`. Она не содержит незавершённые первые блоки A.
- Для уже начатой работы B: сначала сохранить её в своей ветке; затем получить подготовительную ветку и перенести только названный подготовительный коммит. Не выполнять reset/checkout поверх незакоммиченных изменений. При конфликтах общих документов разобраться в содержании, не выбирать автоматически всю сторону.
- Для новой копии: клонировать весь репозиторий, получить подготовительную ветку, создать свою рабочую ветку от её проверенной вершины.
- Итоговые изменения A/B интегрировать отдельным этапом после проверки границ, сборки и визуального просмотра. Не объединять чужую ветку без задачи пользователя.
- Не пушить main и не публиковать Pages без отдельного разрешения. В текущем workflow публикация запускается только push в main либо явным workflow_dispatch. Разрешённый push подготовительной ветки не является разрешением менять workflow/доступ/публичный сайт.

## Проверки

- `npm ci` в новой копии, затем `npm run check` / `npm run build` (build уже включает check). Node 24; базовый lockfile сохранять.
- Браузерные средства уже есть: dev-зависимость `playwright-core` и доступный Chrome/Edge. Дополнительный Playwright skill не нужен. Не отключать защиту ради навыков и не запрашивать новые ключи для необязательных платных API.
- Проверять desktop и телефон 320/390px, промежуточные состояния вступления, клавиатуру/фокус/Escape, отсутствие переполнения и перекрытий, быстрый/обратный скролл, reduced motion и no-JS. После shared-изменений проверять и действующий блок команды.
- Не перехватывать wheel/touch, не оставлять невидимый текст и длинные пустые pin-сцены. Не записывать видео: пользователь отказался; нужны локальный интерактивный просмотр и скриншоты.
- В отчёте: ветка/commit, проверенный URL, изменённые файлы, проверки/ограничения. Нельзя объявлять localhost ссылкой для заказчика из интернета или заявлять физический iPhone/Safari без проверки.

## Данные, инструменты и артефакты

Нет backend, настоящей отправки формы и админки. Не выдумывать цены, отзывы, ФИО/квалификации, лицензию, обещания результата или доступность хирургии. Демоматериалы подписывать. Применять штатный ImageGen, если он доступен аккаунту и нужен; файл imagegen SKILL.md сам по себе инструмент не предоставляет. Не включать платные внешние API без разрешения.

В коммиты не входят секреты, `.env`, токены, `node_modules`, `dist`, `work`, диагностические кадры и локальные runtime-пути. Третьесторонние навыки передаются целиком с соответствующими лицензиями. Не менять движок Scroll Craft под проект; новая вёрстка/эффекты остаются в коде сайта.
