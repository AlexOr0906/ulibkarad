# Карточки и подробный профиль врача

Preview: http://localhost:4192/team-profile-preview/. Ветка `feature/doctors-profile-refresh`. База разработки `6823962` (сохранённый этап доступности); при fetch обнаружен `origin/main` b47329c, возвращающий прежнюю демокоманду. Doctors.astro и восстановленная на главной коллекция в этом изменении не затрагиваются. Для независимой интеграции переносится только коммит этой задачи, не вся предыдущая ветка.

## Подключение

- Новый `DoctorProfileCollection.astro`: props `doctors: readonly DoctorProfile[]`, `preview?: boolean` (по умолчанию false). Его можно подключить в существующей зоне команды после одобрения. Эта задача не подключает его к главной.
- Переиспользован `DoctorCard.astro`: новый opt-in `presentation="profile"`, `profileTarget="#уникальный-id-profile"`. Без него старая карточка работает как прежде. Новые стили только с префиксом dp-.
- Подробное содержимое `DoctorProfileContent.astro` переиспользует `DoctorInformation.astro` и всю существующую модель профессиональных сведений.
- Без JS все профили отрендерены сервером в доступных details/summary. JS перемещает тот же контент в native dialog, не дублируя его; Escape, закрытие кнопкой/вне окна, Tab/Shift+Tab, возврат фокуса. Якорь на профиль поддерживает прямое открытие в preview.
- Данные примеров `src/data/doctor-profile-examples.ts` нельзя переносить в `clinicDoctors`. ФИО и сведения здесь являются обозначениями полей, не выдуманными врачами. Количество примеров не отражает размер команды.
- Дополнительные необязательные поля DoctorProfile: directions, introduction (fallback summary), firstAppointment.description/preparation/duration, booking.href/label. Пустые разделы скрываются. Пока booking не задан, кнопки записи нет. Для записи допустим утверждённый https/tel/mailto или путь внутри сайта; локальные пути получают BASE_URL. Выбор конкретного рабочего способа остаётся задачей клиники.
- Фото: portrait.position/fit для карточки; profilePosition/profileFit для профиля. Fit cover обрезает, contain сохраняет кадр целиком. Пропорции лица не меняются, фильтры/ретушь не применяются. Уникальные стабильные doctor.id обязательны; одну и ту же коллекцию не дублировать на странице с одинаковыми IDs.

## Материалы от клиники

1. ФИО, специальность, должность и согласованное краткое представление от врача.
2. Подтверждённые направления работы.
3. Основное/дополнительное образование: организация, специальность/программа, квалификация, годы.
4. Аккредитация/сертификат: специальность, организация, номер, даты выдачи и действия; категория, если есть.
5. Утверждённое расписание и информация о первом приёме, подготовке и продолжительности (если публикуются).
6. Рабочий способ записи и точный адрес перехода. Не имитировать онлайн-запись до его подключения.
7. Портреты с разрешением на публикацию, желательно от 1200×1500, белый фон, мягкий нейтральный свет, свободное место над головой и вокруг плеч. Для неоднородных исходников подобрать положение отдельно в двух форматах. Исходники сохранить; внешность не изменять.

## Референс и ограничения

В браузере изучены https://ortho.bar/doctors/ и переход в профиль: крупный портрет, имя/специальность, направления, образование и первый приём. Чужие тексты, врачи, фото, отзывы, цены и медицинские утверждения не использованы. Упомянутые клиентом дополнительные скриншоты в этой задаче не были приложены.
Использованы прежние локальные AI-портреты с серебристым исходным фоном внутри белых карточек. Это не финальные фото сотрудников. Никаких новых изображений и изменений внешности.
