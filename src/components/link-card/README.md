## Дизайн и реализация

Мобильная визитка с оригинальной серебряной семейной эмблемой, локальными Cormorant Garamond 400 и Manrope. Белая поверхность, графитовая главная ссылка, серебристая secondary-ссылка. Desktop ограничен 480px. Компактный бренд и действие идут перед дополнительными ссылками. Однократное CSS-появление 650ms; reduced motion отключает его, без JS всё содержимое доступно. Внешних шрифтов, формы, сбора персональных данных, аналитики, backend и платных сервисов нет. Данные редактируются в проекте; самостоятельная админка не обещается.

- src/data/link-card.ts — модель, настройки и ссылки. Факты берутся из contactDetails и clinicConfirmed, а не из новых предположений.
- linkCardSettings.showPending=false скрывает неподтверждённые пункты; social/directions заполняются только утверждёнными ссылками.
- LinkCard.astro — представление; link-card.css — изолированный lc-префикс.
- Основной сайт, контакты, врачи, направления и Пациентам используют BASE_URL. На localhost ведут в локальную сборку; при размещении рядом с основным сайтом — в фактический корень сайта. Текущий публичный сайт: https://alexor0906.github.io/ulibkarad/.
- Переход «Обсудить визит» ведёт к существующему разделу контактов, не имитирует подтверждённую запись. Реальная отправка отсутствует.
- Телефон, соцсети, адрес/маршрут не предоставлены; отображены неактивными строками. Обзор города не используется как точка клиники.

## Локальный просмотр и проверки

npm run build; python -m http.server 4216 --bind 127.0.0.1 --directory dist

http://localhost:4216/link-card-preview/

Собственный локальный процесс 4216 обслуживает dist текущей копии. npm run build: 120 файлов, 0 ошибок/предупреждений/подсказок, 33 маршрута. scripts/verify-link-card.mjs: 320/390/768/1440, reduced motion, no-JS, длинная подпись главного действия, клавиатурный фокус, отсутствие overflow, загрузка эмблемы, HTTP 200 реальных ссылок и переход на основной сайт. Все шесть сценариев прошли. Кадры 390 и 1440 просмотрены. Диагностика work/verification/link-card не коммитится. Физический телефон/Safari не проверен.

## Что нужно для завершения отдельной задачи

Согласовать состав и порядок кнопок, стоимость/объём, постоянный домен и HTTPS-адрес; получить утверждённые телефон, соцсети, адрес/точку клиники и рабочий способ связи/записи. На печатном QR должен быть постоянный HTTPS-адрес на выбранном клиентском домене. Содержимое страницы или назначение перехода можно будет изменить позднее, сохранив этот адрес. Домен сейчас не регистрируется, финальный QR не создаётся. Localhost, текущий preview и GitHub Pages не назначаются окончательным адресом на упаковке. После согласования отдельно решить размещение и поддержку; эта проба не создаёт обязательств по запуску или администрированию.
