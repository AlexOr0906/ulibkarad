# Общие функции OrthoFamily

Ветка `feature/site-functions`, база `0a9eafc7d01a405995440df586993a07d2d98546`. Main/Pages не обновляются.

## Поиск и карта

- `/search/`: форма, клавиатура, состояние загрузки, пустой запрос, отсутствие результатов, ошибка загрузки с выходом на карту. Запрос сохраняется в `?q=`, работает прямая ссылка/back. Текст запроса и результаты выводятся через textContent, без интерпретации HTML. Поиск выполняется в браузере, запросы не отправляются внешнему сервису и не сохраняются в аналитике.
- Индекс строится из main семи реально собранных HTML-документов на `astro:build:done`, без ручного дублирования содержания. Script/style/svg/dialog исключаются, HTML-сущности декодируются. `dist/search-index.json` — производный артефакт, не коммитится. Изменение astro.config.mjs необходимо только для этого build-hook, зависимости не изменялись.
- В Astro dev, пока build-индекса нет (404), поиск читает HTML только тех же семи страниц. При сетевой ошибке показывает понятный выход, не заявляет об отсутствии совпадений.
- `/sitemap/`: пользовательская карта из `src/data/site-pages.ts`. Этот явный список — единственный реестр поиска/карты. Включён исторически названный публичный `/orthodontics-concept/`, потому что это текущая согласованная страница ортодонтии; остальные concepts/preview/compare исключены. Служебные search/sitemap/accessibility также не входят в индекс.
- Поиск без учёта регистра, е/ё эквивалентны, все слова запроса должны встречаться как подстроки; совпадения в названии выше. Морфологический анализ и поиск внутри PDF не реализованы. После добавления документов их описания на странице индексируются, текст самих файлов — нет.
- Без JavaScript поиск не притворяется рабочим: форма скрыта, остаётся карта страниц. Карта полностью доступна без JavaScript.

## Режим чтения

`/accessibility/`, ссылки «Чтение» в шапке и «Настройки чтения» в футере каждой страницы. Три размера текста (18/22/26 px базового текста), три темы контраста (чёрный/белый, белый/чёрный, тёмный/светло-жёлтый). Режим перестраивает сложную композицию в вертикальный поток, снимает фиксированные высоты/позиционирование/маски, отключает движение и увеличивает межстрочные интервалы. Декоративная сцена ортодонтии заменена статичным демонстрационным изображением, её тексты остаются доступны.

Настройки применяются до первого отображения через общий ReadingHead и сохраняются в localStorage `of-reading`. Они восстанавливаются при pageshow/back-forward и storage-событии. Кнопка возврата восстанавливает обычный вид. Если хранилище запрещено, применяется текущая настройка и выводится сообщение о невозможности сохранения. При отключённом JavaScript элементы изменения настроек скрыты, объяснение и ссылки доступны.

Стили изолированы атрибутом `html[data-reading=on]`. Обычный дизайн и сцены не переписываются. Это пользовательский режим, а не декларация соответствия стандартам или замена отдельному аудиту доступности.

## Настоящие сведения о врачах и прайс

- `src/data/doctor-information.ts`: тип DoctorInformation для должности, основного/дополнительного образования, сертификатов/аккредитаций (специальность, организация, номер, даты), категории и расписания. Состав обязательных сведений должен подтвердить ответственный клиники по исходному плану; тип сам по себе не подтверждает юридическую полноту.
- В `DoctorProfile.professionalInformation` передаётся этот объект или null. `doctorInformationRows` выводит только заполненные данные. Компонент DoctorInformation используется готовым ServicePageContent; существующая карточка DoctorCard передаёт сведения в диалог команды, где они выводятся безопасными текстовыми узлами. Пустые поля не создают фиктивных разделов. Фактических значений нет.
- `src/data/service-page.ts`: ServicePrice расширен полями code/category/note, сохранил label/amount/unit. ClinicPriceList задаёт RUB, дату действия, утверждающего, документ и items. `clinicPriceList` пустой, без демонстрационных сумм. Готовый ServicePageContent принимает items через существующий pricing ready-контракт; коды/единицы/примечания выводятся тем же компонентом. Неподтверждённый прайс не подключать как ready. Деньги форматируются через Intl.NumberFormat.
