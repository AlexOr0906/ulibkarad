# Контакты и футер «Ортофэмили»

## Независимая передача

Ветка `feature/contacts-footer` создана от общей основы `3ae89030c1a18ade06800019b8f4a3d2482e834d`. Она не основана на работе врачей и не содержит её коммитов. Врачи сохранены локально и на origin в `feature/doctors-section`, вершина `b43abbdeb9ff4eedc1516453b48c45207cb0aa16`.

Это отдельная проба для интеграции основным разработчиком. Корневая страница, прежние Contacts/Footer, hero, услуги, врачи, глобальные CSS, package.json, lock и shared-компоненты не изменялись. Новую версию не подключали к основной странице. Достаточно перенести только коммит этой задачи на ветку, где уже есть общая основа.

## Решение

Сохраняются Manrope и роли палитры: белый #FFFFFF, светлая основа #EBE9EB, серебро #C9CDD1, графит #292D30, вторичный текст #5B5F62. Крупный левый заголовок, компактная контактная колонка и большая серебристая плоскость под карту. На телефоне контакты идут перед картой; действия остаются рядом с контактами. Графитовый футер завершает страницу крупным названием и неизменённой семейной эмблемой, затем навигацией, документами и реквизитами.

Изучены главная, контакты и футер https://inwhite-medical.ru/ в браузере: отдельная колонка контактных данных, соседний медиаблок, ясное разделение навигации, контактов и юридической информации внизу. У нас не заимствованы их фотографии, данные, тексты, шрифт или география. Абстрактные окружности в заглушке не являются планом города, точкой клиники или схемой проезда; заглушка явно подписана.

Применены принципы frontend-design и Scroll Craft: самостоятельная композиция в рамках брифа, нативный поток, доступное содержание с первого кадра, реакции только на пользовательское действие. Нет новой тяжёлой сцены, pin, скролл-перехвата, видео или ожидания анимации. Это не новый сайт; глобальный fingerprint registry не менялся.

## Файлы для интеграции

- `ContactsSection.astro` — контакты, демонстрационный CTA и слот карты.
- `ClinicFooter.astro` — название, эмблема, навигация и статусы документов/реквизитов.
- `../../data/contacts-footer.ts` — структурированные контакты и документы (пути от этих компонентов).
- `../../styles/contacts-footer.css` — автономные правила с префиксом cf-. Оба компонента сами импортируют файл; общий CSS не требуется.
- `src/pages/contacts-footer-preview.astro` — отдельный просмотр, не обязателен для финальной главной.
- `scripts/verify-contacts-footer.mjs` — проверка взаимодействий и адаптивности.

Пример вставки основным разработчиком после решения об интеграции:

```astro
---
import ContactsSection from '@/components/contacts-footer/ContactsSection.astro';
import ClinicFooter from '@/components/contacts-footer/ClinicFooter.astro';
---
<ContactsSection />
<ClinicFooter />
```

У родительской страницы должны существовать `#top`, `#services`, `#approach`, `#doctors`; `#contacts` создаёт сам ContactsSection. Удалите прежний Contacts/Footer при интеграции, чтобы не дублировать футер и id. Пока это только инструкция: никаких общих файлов эта задача не меняет.

`ClinicFooter` принимает `homeHref` (по умолчанию BASE_URL). Если интегрируете на отдельный новый маршрут, передайте его, например `homeHref={import.meta.env.BASE_URL + 'orthofamily-preview/'}`. Навигация использует существующий `navigation` из `src/data/site.ts`; проверьте соответствие якорей на итоговой странице. Все файлы изображений и ссылки учитывают Astro BASE_URL.

## Наполнение

Подтверждён только город Магнитогорск. В `src/data/contacts-footer.ts` остальные значения равны null; не заменяйте их вымышленными сведениями.

Для `contactDetails` нужны согласованные адрес, телефон (отдельно label и tel: href), часы и email. Телефон/почта становятся ссылками только после наполнения; до этого они обычный текст. `ContactsSection` также принимает типизированный `contacts` prop для будущих вариантов и тестирования.

`Обсудить визит` сейчас раскрывает честное пояснение: запись недоступна, обращения не принимаются и не отправляются. Здесь нет формы и сбора данных. После получения реальных контактов основной разработчик может заменить раскрытие подтверждённым способом связи или подключить отдельно согласованный сценарий записи. Никаких фиктивных рабочих телефонов и кнопок отправки нет.

Карта подключается через именованный слот `map` только после подтверждения адреса:

```astro
<ContactsSection>
  <!-- Здесь согласованная схема или реальная карта с доступным названием. -->
  <div slot="map">…</div>
</ContactsSection>
```

До этого нет iframe, картографических SDK, координат и маршрута. Подключать геолокацию не требуется. Стандартная заглушка заменится слотом полностью; подпись под картой также нужно согласовать с реальным состоянием.

В `informationDocuments` заполните относительный путь `href` только после появления согласованного документа в проекте. При null выводится текст «Готовится», не ссылка. Реальное юрлицо, ИНН/ОГРН и реквизиты лицензии добавляются в ClinicFooter только по документам клиники; сейчас внутри нативного details — подписанные места без придуманных номеров.
