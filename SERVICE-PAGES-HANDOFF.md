## Минимальный контракт общего шаблона услуг

Предлагаемый контракт для B: общий шаблон принимает title/description, сведения hero и **default slot для тела услуги**, а также необязательный named slot **`scene`**. Он управляет общими хлебными крошками, единственным h1, ширинами и оболочкой. Он **не знает**, что нарисовано в visual, не задаёт ему ортопедические transform/маски/прогресс и не содержит медицинских текстов услуги.

Пакет A будет разделён так:

1. **`OrthopedicsPageContent.astro`** — тело услуги: секции h2, placeholders утверждённых текстов/врачей/прайса/контакта; без html/body/main/h1 и общей шапки/футера. Props: `doctorsHref`, `contactHref` (через BASE_URL по умолчанию), `autoMotion` (true по умолчанию).
2. **`OrthopedicsVisual.astro`** — независимый visual для named slot. Props: `id`, `autoMotion` (true по умолчанию). Внутри только иллюстрация/подпись и локальная хореография, без h1/hero-title/общего контейнера. Композиция адаптируется по ширине, не зависит от маршрутизатора.
3. **`OrthopedicsPreviewIntro.astro`** — временная локальная композиция заголовка/визуала для просмотра до доставки шаблона. Это не shared service-компонент; при итоговом подключении её заменяет hero шаблона B.
4. **`orthopedics-motion.ts`** — идемпотентные локальные initializer/cleanup. Никаких общих router hooks; B подключает lifecycle в одном месте при интеграции. Reduced/no-JS, быстрые якоря и back/forward не оставляют скрытых блоков.
5. **`orthopedics-preview.astro`** — только preview-композиция existing InternalPageLayout + временный Intro + PageContent. Не production route услуги и не новый общий layout.

Секции тела используют собственные `.or-shell`, а полноширинные поверхности остаются вне дополнительного узкого контейнера. Если общий шаблон задаёт контейнер, согласовать один уровень, не суммировать боковые поля. Сцене достаточно отведённого scene-slot; она измеряет собственную видимость, не добавляет pin/spacer и не перехватывает wheel/touch.
