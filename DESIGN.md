# Общая визуальная основа OrtoFamily

28 октября 2026. Бриф клиента выше общих рекомендаций навыков. Здесь разделены текущая техническая база и предложения нового вступления; предложение не считается согласованным только потому, что попало в CSS.

## Предложение A для нового вступления, пока на обсуждение

Это ограниченная фотографическая редакционная композиция, а не глобальное переоформление всего сайта. Предлагаемые локальные токены: холодная бумага `#EEF1F3`, светлая поверхность `#F5F6F6`, графит `#273037`, светлый текст `#F2F4F5`, вторичный тёмный текст `#596770`, прежнее серебро `#C9CDD1`. Это техническое предложение, не новое утверждение палитры заказчиком.

- Текстовый знак **OrtoFamily** и подпись **«Стоматология · Ортодонтия»** подтверждены по нижнему левому варианту брендборда. Для знака нужен контрастный шрифт с засечками; точный шрифт не установлен. Текущее близкое временное исполнение — локальный Cormorant Garamond 400, @fontsource/cormorant-garamond 5.3.0, OFL. Это не заявление о точном совпадении. Остальной текст остаётся Manrope 14–16px, межстрочный 1.55–1.85. Подлинная семейная эмблема не перерисовывается. Красная отметка выбора в дизайн не переносится.
- На desktop широкая композиция с независимыми фотопланами; на телефоне вертикальная, ранний CTA и меньше тяжёлых слоёв. Фотографии не проходят по читаемому тексту.
- Контейнер до 90rem. Предложение боковых полей: 56px на широком экране, 32px на планшете, 16px на телефоне. Базовая шкала 4/8/12/16/24/32/48/64/96px с уместными fluid clamp.
- Скругления служат фотографическим кадрам, не превращают каждый блок в одинаковую карточку. Направления — компактные раскрытия, не четыре одинаковые большие плитки. Без декоративных меток/счётчиков, не несущих смысла.
- Основное действие одинаково называется «Обсудить визит». Пока это демо без отправки и записи; смысл действия не маскируется.
- Сильный акцент один: короткий светло-графитовый фотопереход. Остальное движение отвечает вводу пользователя или поддерживает чтение; не набор повсеместных fade/slide.

## Правила движения и доступности для обоих разработчиков

Нативная прокрутка. Не вызывать setPointerCapture/requestPointerLock, не перехватывать вертикальные wheel/touch. Эффекты ограничены своей сценой и не добавляют пустую длину страницы. Main copy не остаётся полупрозрачным/невидимым; быстрый и обратный скролл должны давать читаемую страницу.

`prefers-reduced-motion` оставляет красивую статичную композицию и доступное содержание. Без JS сохраняются смысл и доступные нативные раскрытия/ссылки; никаких активных кнопок, которые только выглядят рабочими. Мобильный вариант не зависит от hover. Фокус видим, модальные окна закрываются по Escape и возвращают фокус, контент не перекрывается шапкой с зазором сверху.

Новый CSS изолировать собственным префиксом (`of-*` у вступления, локальный префикс у команды), а не переопределять старые общие селекторы. Смена shared-токена требует просмотра также команды.
